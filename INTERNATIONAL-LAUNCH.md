# MusiCup international launch guide

## Recommended public link

Use the English GitHub Pages entry for the first overseas release:

<https://vulpexy.github.io/composer-world-cup/?lang=en>

GitHub Pages is the safer default for an international audience because it is globally distributed, HTTPS is already configured, and the repository URL makes the project's open-source nature easy to verify. Keep <https://worldcupforfun.cn/composer/?lang=en> as the Chinese mirror. If overseas traffic becomes sustained, the long-term option is a short neutral domain routed through an international CDN to the same static build.

## Where to share

1. **Reddit** — start with communities whose rules permit self-made classical-music projects. Explain the project, disclose that you made it, and participate in the discussion; do not repeat the same promotional post across many communities.
2. **Bluesky and Mastodon** — suitable for a public playable link, a result image, and searchable classical-music hashtags.
3. **Instagram and TikTok** — use a short screen recording showing “choose 48 → groups → revival → bracket → champion”; put the playable URL in the profile or link field.
4. **Discord communities and specialist forums** — ask moderators before posting, especially where self-promotion is restricted.

Suggested tags: `#ClassicalMusic #Composer #MusicHistory #IndieWeb #VibeCoding`.

## Suggested launch copy

> I made MusiCup, a free Classical Composer World Cup built with AI-assisted coding. Choose 48 composers, compare them in twelve pitch-named groups, revive eight favourites, and play a complete knockout bracket. It is subjective by design: the fun is discovering where your own listening preferences lead. No account is required. Play in English: https://vulpexy.github.io/composer-world-cup/?lang=en

When posting, attach a clear cover image and one completed bracket. State that this is your own project and that it is free and non-commercial.

## Operations checklist

- Test the English link in a private/incognito window on iOS Safari and Android Chrome.
- Test at least one Wikimedia recording and one Apple preview on Wi-Fi and mobile data.
- Keep the GitHub Issues link visible for track mismatches, licensing corrections, and accessibility reports.
- Watch GitHub Pages traffic and the results API for unusual spikes. GitHub Pages is suitable for this small static project, but it is not intended as unlimited commercial hosting.
- Never copy or upload preview audio into the repository. Keep playback streamed from its identified source.
- Recheck third-party audio links periodically because catalogues and territorial availability change.
